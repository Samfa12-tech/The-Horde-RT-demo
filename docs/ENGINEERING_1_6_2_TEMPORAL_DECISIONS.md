## DRS portable assessment

`src/graphics/BoundedDynamicResolution.h` is a dormant CPU prototype, not connected to the runtime and not a Graphics toggle. It accepts fence-owned GPU submission identities plus actual timestamp resolution/ticks, successful presentation and foreground/cap/transition status. Duplicate/out-of-order submissions cannot advance dwell. Nonfinite/zero timings, fewer than32 ticks, resolution coarser than1% of target, background, capped or transitioning observations clear load history and freeze proposals. GPU time alone cannot characterize pacing bottlenecks; presentation/loop evidence is still required before connection.

Policy: EWMA0.2, slow threshold108% with3 consecutive readings, headroom threshold82% with12, at least30 valid readings between changes, bounded5-percentage-point steps, explicit50..100% limits. Requests do not change effective scale. Only matching successful resize completion commits; failure retains the effective value and requires fresh dwell. Startup/lifecycle/settings changes require Reset. Host tests cover steady load, slowdown/recovery, deadband, caps, invalid timing, duplicate collections and transaction failure. Tick/period duration must agree with reported GPU milliseconds within2 ticks or1%, catching unit/identity mistakes. This is hysteresis correctness, not a claim of thermal/device stability.

Admission: **unadmitted** until reliable launcher timing maps observations to their presented owning frame, with timestamp granularity, caps, foreground state and resize transaction results. Require fixed75% comparisons, thermal sustained runs and oscillation/quality captures on RTX and the allocated Android device. Current fixed-resolution settings remain authoritative; no silent scale reduction.

## Actual temporal geometry vertical slice

`src/graphics/TemporalGeometryHistory.h` implements bounded CPU previous-frame ownership and a shared geometry motion producer. Its camera projection matches `rt_frame.glsl` including walk origin/pitch and aspect/FOV. Objects supply actual post-deformation local vertices plus world transforms and stable identity/topology generations. Motion projects the same triangle barycentrics through previous/current poses and transforms. Tests distinguish camera motion, rigid transform motion and deforming-vertex motion; a camera-only substitute would fail the latter tests. Signed motion is previousUV-currentUV in unjittered UV units, and depth is forward view depth; SDK adapters must explicitly convert their coordinate/depth conventions.

Commit requires successful submission **and** presentation with monotonically increasing owner sequence. Retry, cut/checkpoint, preview, lifecycle, backend/settings, resize and failed frame invalidate history. Reactive glass/water/flame/volume/miss cases, changed identity/topology, invalid indices/barycentrics, offscreen projection and dimension mismatch cannot reuse it. Previous primary depth/normal/identity comparison rejects disocclusion candidates. Limits32 objects/4096 vertices bound retained deformation storage; caller spare vector capacity is repacked away. Proposed attachment arithmetic checks overflow: depthR32F4 + motionRG32F8 + current/historyRGBA16F16 + validation4 =32 bytes/pixel, or66,355,200 bytes at1920x1080, before output/alignment/scratch/previous geometry. This is an estimate, not measured GPU residency.

Admission: **CPU foundation only**. No runtime scene producer, GPU primary depth/motion attachment, previous pose descriptor, HDR intermediate, confidence/history attachment or reconstruction pass is connected. Both production launchers currently write tone-mapped/sRGB/swizzled RGBA8. First-hit motion cannot describe reflected/transmitted/volume radiance; those must remain invalid/reactive until proven. The next GPU slice must wire actual world/viewmodel/enemy deformation including cadence/skipped poses and bucket identity, prove resets/barriers/resize rollback and memory on both launchers, and inspect moving/disoccluding edges. No temporal accumulation or vendor upscaler is admitted by the CPU tests.

## Optional material/geometry decisions

Detail normals: **defer**. Base normal strength, UV authoring and tangent policy now have a shared path; an extra texture/sample needs matched material detail benefits and sustained mobile cost first. No invented detail slider or default asset retune.

LOD: **defer**. No measured distance-dependent geometry/bandwidth bottleneck or validated reduction/identity cadence is established. Changing RT meshes would additionally invalidate topology/history and require BLAS cost/evidence. This work does not import a general LOD renderer.

Parallax: **deferred by contract**. Real silhouette, occlusion and collision changes use geometry. Normal detail remains authored surface detail, without fake traversal or scene-specific shadow tricks.
