## Proposed runnable slices

1. **M1 imported normal scale.** Add `StaticMaterial::normalScale = 1`. Import cgltf scale when a normal texture exists and include it in finite material validation. Append `normalScaleUvScaleBlend` to ABI at offset112, making size128: X = tangent XY multiplier, Y/Z = positive UV multipliers, W = normal blend. Imported defaults are `(1,1,1,1)`. `RtStaticMeshSlot::ConvertMaterial` fills every field explicitly because generated default arrays are zero. Shader normal scaling applies before existing TBN mapping. Keep size/ranges and both launchers in sync. Maximum existing32-record buffer growth is512 bytes; report actual allocation changes rather than asserting texture growth.
2. **M2 authoring/tangent policy.** Extend `MaterialOverride`/`ParseMaterialOverrides` with optional normalScale and textureScale using existing presence flags and material-name resolution. Missing fields leave imported values intact. Use finite signed normal strength; positive bounded repeat scales with clear diagnostics. UV multiplication affects base, normal, ORM and emissive consistently. Existing atlas UVs default to1 and remain opt-in; do not automatically tile player/lantern atlases. Add perpendicular fallback for no-map/no-tangent geometry only. Document metres, repeats/metre, OpenGL/glTF +Y normals, tangent W, transform baking and real geometry versus baked normal detail in `docs/ASSET_PIPELINE.md`.
3. **M3 dungeon authoring.** Reuse the same ABI record and TBN/strength helper for dungeon array materials, while retaining the authored projection basis and explicit `(normalScale=1, uvScale=0.42, normalBlend=0.34)` defaults. Resolve five world material records through deterministic metadata, not a new bump subsystem or object branches. One bounded design is append the records after existing imported records and pack their absolute material index into unused upper surface-code bits; validate total material capacity before allocation and preserve lower material/normal code bits. Decide exact indexing with preview ownership before editing scene/descriptors. A capacity increase, if needed, must reflect actual roster and tests, not silent budget growth. Authorable scale belongs to asset/material data, not a global decorative Graphics slider.
4. **M4 AO policy.** Add `HitInfo::occlusion` default1, retain pure albedo in `h.base`, and put ORM/ARM AO into occlusion. Multiply only established unoccluded ambient/indirect approximations; do not attenuate direct torch/local/moon/emissive or RT visibility already computed. Inspect primary and terminal secondary paths together. Keep this as its own visible correction and acceptance evidence, with no exposure/light-strength retune.

Meaningful affected tests: extend `StaticGltfAssetTests.cpp` fixtures for missing scale, 0/0.5/1/2 and finite negative scale, invalid nonfinite values, no normal map, missing/degenerate tangents, both handedness signs, stable untextured +/-XYZ fallback, positive nonuniform transforms, and explicit negative-node rejection. ## Temporal feasibility boundary

`rt_frame.glsl` constructs the exact camera including current walk-dependent origin/pitch, shades, composites volumes, tone maps/sRGB converts, swaps channels and writes RGBA8 directly. `RtSceneAbi` has no previous camera, object transforms, deformation history, jitter, depth/motion output or history descriptors. Scene output resizing replaces one output image transactionally after idle; there is no history to preserve today. Consequently DLSS/SGSR or temporal denoising is not a small plug-in patch over existing inputs.

After fixed-resolution transactions and timing are verified, a finite off-by-default vertical slice can:

- Own current/previous camera projection matching the actual ray construction, jitter and render/output dimensions in one shared frame record. Reset history for retry/reset, camera cuts/checkpoints, preview entry/exit, lifecycle/backend/settings changes, resize and failed submission/presentation. Commit previous state only for its successful owning frame, preserving fence/evidence authority.
- Output finite linear primary depth and motion from actual hit identity/barycentrics into optional images for both launchers. Static hits reproject through previous TLAS transforms. Deforming player/viewmodel/skeleton/lich require previous positions or previous skin matrices with stable vertex/primitive identity, including skipped skin cadence and pose-bucket reassignment. Camera-only motion is an explicitly incomplete prototype, not whole-scene support.
- Treat misses, emissive volumes, water/glass composites, new topology/identities and uncovered pixels as explicit invalid/reactive cases. Do not call first-surface motion sufficient for transmitted/reflected radiance. Bound history confidence and disocclusion using depth, normal and stable identity; never accumulate invalid samples to conceal artifacts.
- Add linear HDR current/history only when testing reconstruction; current post-tonemapped BGRA-corrected RGBA8 is not suitable temporal radiance history. Resize all optional attachments transactionally with rollback and tracked allocations, barriers, descriptors, cleanup and backend parity. Two input images at4 bytes/pixel each already cost about16.6MB at1920x1080, before history/deformation buffers; this is a storage estimate, not measured residency/bandwidth/performance.

DRS remains a separate feasibility decision: use valid GPU/frame timing, quantized min/max dimensions, hysteresis and minimum dwell; test stable load, step changes, invalid timings, thermal slowdown, caps and sizing failure. CPU command-record time is not GPU cost; pause/menu samples must not drive game quality changes. Show requested/effective scale truthfully and retain fixed75% comparisons. Do not expose DRS before oscillation-free real-device sizing is proven.

Disposition now: **defer** vendor upscalers, detail normals, LOD extension and parallax implementation. Reopen only with measured benefits, the required foundation and SDK/licence/device evidence; adapters and optional texture samples are not mandatory completion gates. Material core and the bounded input feasibility decision remain required. Missing physical evidence is an acceptance gap, not a pass.
