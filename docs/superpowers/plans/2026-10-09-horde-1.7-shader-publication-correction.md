## Source and disassembly diagnosis

The shared changed consumers are primary-ray origin in `rt_frame.glsl` (`+0.70 + delta`), procedural camera-relative normal in `rt_hit_decode.glsl` (`+0.75 + delta`), and staff target in `rt_atmosphere.glsl` (`+0.28 + delta`). The unchanged height delta is read from the second vec4 of binding 20's 32-byte held-light ABI. The earlier shader optimized this entire buffer out: physical lighting uses actual emitter sockets through binding 21. Height therefore activates buffer/interface/type/name/decorations in addition to access/load/arithmetic. Disassembly contains 19 new held-buffer declaration/name/type/decoration instructions (including two pointer types). Opaque's height buffer load is already hoisted once; procedural normal construction is expanded at six inlined sites. Eliminating hypothetical 29 repeated height loads is not a supported diagnosis. [Opcode comparisons](../../evidence/2026-10-09-shader-publication-correction/disassembly-opcode-comparison.json) and archived full disassemblies permit independent inspection. Exact baseline/candidate sources, dependency identities, preprocessing and resolved sources are retained.

The bounded experiments were: (1) invocation-level shared normal/staff reuse, which worsened Generic and left Opaque over; (2) explicitly appended three precomposed target vec4s at binding 20 (64-byte ABI), which also failed; (3) scalar normal subtraction preserving arithmetic order, which worsened both; (4) an explicit absolute-height vec4 appended to the already active quality buffer, improving Generic but still exceeding Opaque; (5) caching that transport only in the fully inlined strategy plus equivalent primary-mask composition; and (6) equivalent quarter-turn predicate and reuse of the same primary-hit distance in its existing consumers. The last complete matrix is retained above. No helper function was added and exact function/call/query contracts were preserved. Intermediate two-row runs are diagnostic subsets and never eight-row acceptance.

For the final **measurement-only** layout: `RtHeldLightGpu` stays 32 bytes, with physical position/strength untouched; `RtQualityControlsGpu` would append `playerWorldY` at offset 16, increasing 16 to 32 bytes. The existing uint4 quality controls stay at offset 0. Its new vec4 explicitly holds eye/normal/staff Y and a zero fourth component; no reserved control or light field is borrowed. The dust upload prefix would consequently move its array from offset 16 to 32 (11280 to 11296 total). The shader-only generator layout and consumer patch are archived, but the CPU producer/dust upload was **not integrated or built**. Thus there is no end-to-end ABI/semantic acceptance for this rejected prototype. It demonstrates a measured cost direction, not a runnable correction. The earlier 64-byte transport experiment likewise has no accepted native proof.
