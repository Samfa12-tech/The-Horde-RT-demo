# WP2 movement and directional animation disposition — 9 October 2026

## Shared movement authority

Player-controlled run is a shared `GameSimulation` state advanced by the existing fixed 60 Hz owner. Android publishes a run-toggle edge from the on-screen RUN button and a held state from controller R1. Windows publishes a toggle edge from Caps Lock and held state from Shift or XInput right shoulder. Both continuous controls and edge counters are carried by `InputSnapshot`; platform code does not move the player directly.

Movement axes are clamped, split into normalized direction and analog strength, and diagonal speed is bounded. Ordinary no-run movement retains its exact existing 1.9 m/s timing; development-route walking and run entry/exit use acceleration and braking. Run reaches a bounded 3.2 m/s target after acceleration, with no stamina drain or automatic outdoor activation. It clears on pause/focus loss, touch cancellation or touch-control restoration, controller suspension/removal, death/checkpoint retry, Keeper reveal, and combat-action interruption. A held key must be released after a clearing interruption before another hold can run. Run is not applied to authoritative replay movement or the authored dodge trajectory.

## Available rig and clip disposition

The rights-cleared runtime rig is `assets/models/player/runtime/gothic-traveller-lod0.runtime.glb` (see the player entry in `ASSET_LICENSES.md`). Its runtime [clip manifest](../../../assets/models/player/runtime/clip-manifest.json) declares only `Idle` and `Walking`. It explicitly excludes `running`, `attack`, and `death`.

| Direction/action | Runtime disposition |
| --- | --- |
| Forward walk | Supported by the existing Walking clip. |
| Backward walk | Supported as backward simulation movement; the rig has no backward-specific clip, so it reuses Walking. |
| Left/right strafe | Supported as independent simulation axes; there are no strafe-specific clips, so the rig reuses Walking. |
| Run | Supported as a movement speed state and faster shared locomotion phase using the existing Walking clip; no run clip is present. |
| Directional dodge | Supported by the existing normalized simulation direction and authored root-motion distance/duration; no dodge clip is present and run speed never scales it. |
| Combat priority | Existing sword, upward-slice, and parry upper-body layers continue to overlay locomotion through `PlayerAnimationState`; this work adds no combat clips or timing. |
| Attack/death animation | Not available in the runtime clip manifest. Combat timing remains simulation-owned; death animation remains an explicit asset gap. |

The focused Vulkan-enabled `horde_rt_player_directional_rig_tests` target loads the rights-cleared GLB through `PlayerRenderSlot`, advances the shared simulation through forward/back/left/right inputs while yaw and pitch remain fixed, skins each resulting real rig pose, and checks both hand attachment socket errors against the existing 15 mm contract. It compares run and walk locomotion phase and exercises forward/back/left/right dodges with run toggled on to confirm the authored dodge distance remains unchanged. The portable `horde_rt_player_animation_tests` target retains the upper-body action-over-locomotion priority check. These are host-side code checks; they do not claim owner-feel or physical-device acceptance.
