## Android acknowledgement protocol

Debug checkpoint207 writes `chapter-start-ack.json` through a temporary file and
rename. Before a new import it retires the prior ready receipt. After successful
staging the new checkpoint generation is recorded as not ready. Only the actual
current submitted simulation tick, nonzero record/submission identities and a
successful RT present can produce ready=true. The receipt carries checkpoint,
checkpoint generation, surface/world generation, tick, scene epoch, measurement
generation and record/submission serial. `HORDE_CHAPTER_START` logs whether the
receipt was saved. GPU completion and display scanout are explicitly not claimed.

A future device controller must observe a NEW `HORDE_BENCH begin` for207 in the
current app process/log interval, then require the saved ready receipt with that
exact generation and current surface, plus nonzero identities. Never accept an
old file alone, guess readiness from elapsed time, or reuse one across process,
surface or checkpoint changes. Motion still independently checks the snapshot
and its existing current completed-frame evidence before arming. An export
failure, pending/failed seed, timeout, or stale identity ends that trial.
