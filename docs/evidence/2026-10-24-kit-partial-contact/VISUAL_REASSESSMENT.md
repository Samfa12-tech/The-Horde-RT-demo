## Three-second 180-degree pacing

In [the existing large-turn movie](four-45-turns-180deg-authored-1x.mp4), motion
runs from **0.500 to 3.500 s**. Each current take lasts 0.75 authored seconds.

- **1.208 / 1.250 / 1.292 s:** the first cycle settles and the next starts.
- **1.958 / 2.000 / 2.042 s:** the same planted exchange repeats.
- **2.708 / 2.750 / 2.792 s:** the third/fourth cycle boundary repeats.
- **3.500 s:** the full 180 degrees is complete and the final hold begins.

No abrupt joint discontinuity is identified at those joins. The visible rhythm
is nevertheless **four separate shuffles**, with repeated brief settles, rather
than one continuous purposeful turnaround. It is physically plausible for a
stationary armored companion, but looks deliberate for a routine lead-off. I
would not call departure responsiveness accepted from this isolated preview.
Actual path/tether context has not been exercised with the proposed shared
state: this is a pacing concern, not a demonstrated route failure.

Do not adopt a three-second default or add assets solely from that duration.
If the context trial shows unwanted waiting, first compare one modest coupled
retiming of the existing joints and yaw, checking foot speed, angular limits and
joins. Do not silently retime, speed up the motor, widen the tether or remove
contact pauses. A larger-angle authored take would need a visible/contextual
reason after that simpler comparison, not this millimetre measurement.
