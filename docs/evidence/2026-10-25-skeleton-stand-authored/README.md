## Bridge state is not an enabled encounter

`SkeletonRevivalBridge.h` is a default-disabled, unwired simulation controller.
It separates protected practice, first fight, consumed signal, rising, rearming,
live fight and completion. Only explicit finished practice plus actual deaths
and an admitted presentation can consume the one-time signal. Skip remains an
opt-out; Retry retains consumption, and validated earned restoration is terminal.
Pause, death or missing presentation cannot run the rise clock. Collider
clearance and an actual two-actor live acknowledgement must precede accepting
the final defeat. No actor, sound, pose, damage, reward or save is changed by it.

The existing simulation currently calls `EnemyDirector::MarkSelectedDead` as soon
as the first skeleton pair is defeated. Future integration must defer that call
only for the admitted bridge path, preserve stable IDs/corpse roots, atomically
revive both actors, and reject temporary practice/rising completion records.
It must not use `SwordCombat::Reset` to teleport/revive actors or run a second
wave after explicit Skip. The controller's signal/rearm timings are provisional;
the rise duration has no default and must come from admitted asset evidence.

The existing combat foundation target passes 918 assertions in 8.48 seconds;
its 30-second deadline and original assertions are unchanged. The initial
916-assertion pass is retained separately: review then replaced the insufficient
`!bothDead` acknowledgement with explicit `bothAlive` for the same pair. One
survivor, stale death snapshots or contradictory flags cannot fake completion.
Tests also exercise one-shot consumption, invalid time/duration, pause/death/
readiness loss, clearance waiting, retry at consumed phases, Skip, replay and
locked earned restoration. These are controller tests, not actual actor revival,
live collision, campaign save/load integration or audio acceptance.
