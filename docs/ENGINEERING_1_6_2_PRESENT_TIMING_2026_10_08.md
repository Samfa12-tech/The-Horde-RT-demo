## Collector and analyzer

`PresentTimingEvidence` borrows the actual device/swapchain on its existing owner thread. It associates nonzero present IDs with committed RT frame identities and records native `VK_GOOGLE_display_timing` results. Actual phone driver inventory confirms the extension. It retains maintenance1 retirement fences, requests desired time zero, makes no frame-pacing wait, and does not rewrite existing CPU/GPU timing definitions. Registration and bounded queries occur after their original CPU frame endpoint; separately reported query CPU time remains included in real inter-present intervals. Ordinary builds compile the integration Off and allocate no collector storage.

Opt-in collector storage is bounded at 32,768 completed rows, 256 pending records, and 65,536 seen-ID slots: **3,932,160 bytes**, plus its small pending state. Each poll makes at most two calls, with a 32-record query batch and no retry/wait loop. Error, missing, duplicate, zero, rejection and capacity counters remain visible. Swapchain retirement drops borrowed handles and explicitly counts unresolved records. Raw unsigned `presentMargin` is preserved; this driver returns implausible near-`UINT64_MAX` values, which are excluded from metrics. An unsigned wrap is a hypothesis, not a certified driver diagnosis.

The standard-library [offline analyzer](../tools/analyze_android_present_timing.py) joins `(sceneEpoch, measurementGeneration, recordSerial, submissionSerial)` to completed owning rows and additionally checks simulation tick, actual scale, output extent, backend, one surface/swapchain, schema/count consistency, contiguous identifiers and strictly increasing nonzero `actualPresentTime`. It rejects loss, unresolved tails and invalid joins with a nonzero exit. It emits raw report SHA-256, exact scope, integer-nanosecond intervals and a rate computed as `(matched images - 1) / (last actual timestamp - first actual timestamp)`. This is an observed image rate within the measured span, not a CPU/GPU reciprocal, scanout completion, photons or sustained free-play FPS. Percentiles use nearest rank; the 33.333 ms threshold is explicitly 33,333,000 ns.

Khronos documents the independent [actual presentation timestamp field](https://docs.vulkan.org/refpages/latest/refpages/source/VkPastPresentationTimingGOOGLE.html) and [asynchronous finite query history](https://docs.vulkan.org/refpages/latest/refpages/source/vkGetPastPresentationTimingGOOGLE.html). The prior SurfaceFlinger latency probes remain closed negatives: display-period headers with no owned-frame triples. [Perfetto FrameTimeline](https://perfetto.dev/docs/data-sources/frametimeline) explicitly does not support SurfaceView, so its availability alone is not game-layer evidence. No global tracing/counter settings were changed.
