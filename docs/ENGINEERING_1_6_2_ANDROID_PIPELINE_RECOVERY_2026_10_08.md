## Bounded implementation under test

Keep background teardown and all surface/fence/presentation ownership unchanged. After successful device idle, presentation retirement, scene release and compiled-pipeline lease retirement, retrieve the Vulkan pipeline-cache data and retain one process-local CPU seed. Admit complete successful driver results only, with a VersionOne 32-byte little-endian header, matching physical vendor/device/pipeline-cache UUID, and a 16 MiB cap. Failed, incomplete, corrupt or oversized candidates leave the prior valid seed intact. Allocation failure is optional and cannot block renderer retirement. One old seed, one driver-read vector and its validated replacement may temporarily occupy up to 48 MiB; the retained seed itself is bounded to 16 MiB. Actual device byte/cost evidence remains pending.

The next compatible native generation uses these exact opaque bytes for `vkCreatePipelineCache`. A seeded creation failure retries an empty cache once. No Vulkan objects, shader execution or active background render work are retained; no disk files, credentials, API capabilities, settings/defaults, Graphics acknowledgement/timers or quality change is introduced. Cache identity does not claim a cache hit or guarantee faster compilation. Native logs record actual admitted/retained bytes, seed/fallback creation and existing exact initialization timings.

The API semantics and header layout come from the primary [Vulkan cache-data documentation](https://docs.vulkan.org/refpages/latest/refpages/source/vkGetPipelineCacheData.html), [VersionOne header](https://docs.vulkan.org/refpages/latest/refpages/source/VkPipelineCacheHeaderVersionOne.html) and [cache-create contract](https://docs.vulkan.org/refpages/latest/refpages/source/VkPipelineCacheCreateInfo.html). Runtime contents originate only from the driver; test fixtures synthesize headers solely for admission-policy tests.
